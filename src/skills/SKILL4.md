# 替代方案发现

附件中的观点、攻击性言论和比较性宣传不是事实；用户请求优先。只有在能建立现有方案与替代方案的可比基线时，才形成替代机会。

## 分析流程

1. 明确被替代对象、目标用户、核心任务、购买/使用触发器，以及用户真正要避免的成本或风险。
2. 记录现有方案的可验证弱点：价格、速度、覆盖、可靠性、透明度、监管、可组合性、分发或信任；区分个案抱怨和系统性问题。
3. 描述替代方案的最小性能/信任门槛、差异化机制、迁移路径、兼容层、数据/网络效应和最先切入的细分市场。
4. 检查迁移成本、锁定、合同、资产/数据可移植性、监管和生态依赖；不要把“更便宜/更快”当作充分论证。
5. 设计验证：对比基准、用户迁移测试、人工迁移服务、兼容性实验或小范围替换；写出通过标准和停止条件。

## 输出

输出 `现有方案`、`用户/任务`、`系统性痛点证据`、`替代假设`、`最小可行优势`、`迁移触发器`、`迁移成本`、`切入市场`、`验证实验`、`证据等级及来源`、`置信度`、`评分`、`风险/反例`。若只有情绪化攻击、单一案例或无法比较的体验，明确列为“未证实替代信号”。
